# Единая схема GSAP-анимации декоративных изображений

## 1. Цель и границы

Документ объединяет правила для desktop- и mobile-версий страницы «Азиатские недели» на основе дизайн-аудита макетов `1920 px` и `428 px` и текущей структуры проекта.

Анимируются только декоративные изображения: акварельные цветы, животные, паспорта, печати и другие presentation-only слои. Контентные изображения не анимируются.

К контентным относятся hero/KV, фотографии партнёров, стран, сезонов, кухни, массажа, курортов, достопримечательностей и отелей. Они могут менять crop, `object-position` или source между breakpoint, но не получают GSAP-трансформации, появления, параллакс или масштабирование.

Анимация карточек, текста, навигации и других UI-элементов не входит в эту схему. Если такая анимация используется отдельно, она не должна захватывать вложенные контентные изображения.

## 2. Базовая модель

Все декоративные элементы получают единый декларативный контракт:

```html
<div
  class="section__decor"
  aria-hidden="true"
  data-gsap-decor="parallax"
  data-gsap-axis="y"
  data-gsap-distance-desktop="6"
  data-gsap-distance-mobile="3"
></div>
```

Обязательные правила:

- `aria-hidden="true"` — декор исключён из accessibility tree;
- `pointer-events: none` — слой не блокирует интерфейс;
- `position: absolute` — декор не влияет на layout flow;
- секция-владелец имеет `position: relative` и контролируемый `overflow: clip` или `hidden`;
- GSAP меняет только `transform` и при необходимости `opacity`;
- исходные координаты, размер и поворот задаются CSS, а не JavaScript;
- один декоративный DOM-элемент принадлежит одной секции и одному GSAP context;
- контентные `img`, `picture`, `coral-image` и фоновые фотографии не получают `data-gsap-decor`.

## 3. Типы движения

| Тип | Назначение | Desktop | Mobile | ScrollTrigger |
|---|---|---|---|---|
| `parallax` | Крупный фоновый декор, частично выходящий за секцию | Смещение по Y на `±5–8%` | Смещение по Y на `±2–4%` | `start: "top bottom"`, `end: "bottom top"`, `scrub: 1` |
| `drift` | Небольшой самостоятельный объект сбоку или над карточкой | X/Y до `16–24 px`, rotation до `±2deg` | X/Y до `8–12 px`, rotation до `±1deg` | scrub по длине секции |
| `reveal` | Декор внутри glass-card, который должен мягко появиться | `autoAlpha: 0 → 1`, scale `0.96 → 1` | `autoAlpha: 0 → 1`, scale `0.98 → 1` | один раз при `top 82%` |
| `static` | Декор, для которого движение ухудшает композицию или crop | Без движения | Без движения | Не создаётся |

Правило выбора: по умолчанию используется `parallax`. `drift` применяется к компактным объектам; `reveal` — только к декору внутри карточки. Если на mobile элемент сильно обрезан, перекрывает текст или вынесен за viewport, он становится `static` либо скрывается CSS.

Для Китая и Вьетнама поля `decor`, `imageLeft` и `imageRight` сейчас пусты. После добавления ассетов они автоматически включаются в ту же схему по роли, без отдельной country-specific логики.

| Группа | Примеры | Поведение |
|---|---|---|

| Погода / сезоны | `/winter.jpg`, `/spring.jpg`, `/summer.jpg`, `/fall.jpg` | Статичны |
| Кухня и массаж | `/tai-kyhnya-m.jpg`, `/thailand-massage.jpg` | Статичны |
| Курорты | `/phuket.jpg`, `/samui.jpg`, `/pataya.jpg`, `/krabi.jpg` | Статичны, включая движение carousel track |
| Достопримечательности | `/chalong.jpg`, `/antong.jpg`, `/naghon.jpg` | Статичны, включая движение carousel track |
| Hotels / story backgrounds | `/hotels-bg.jpg`, `/country-story-m.jpg`, `/country-story-d.jpg` | Статичные фоновые поверхности |

Перемещение слайда Embla не считается анимацией изображения: движется track как часть управления каруселью, а не само изображение относительно своей карточки.

## 5. Responsive-правила

### Desktop

- Допустима полная амплитуда параллакса, так как вокруг основного контейнера больше свободного пространства.
- Одновременно двигаются не более двух крупных декоративных слоёв в одной секции.
- Соседние слои используют разные амплитуды или противоположное направление, но остаются медленнее прокрутки страницы.
- Запрещены бесконечные автономные циклы: движение связано со scroll progress.

### Mobile

- Амплитуда составляет примерно `40–60%` desktop-значения.
- Rotation минимален или отключён.
- Если декор скрыт CSS или полностью находится вне viewport, ScrollTrigger для него не создаётся.
- Декор не должен пересекать заголовок, основной текст, CTA и controls ни в одной точке scrub-анимации.
- Для промежуточных ширин `768`, `1024` и `1280 px` амплитуда выбирается через `gsap.matchMedia()`, а не через определение устройства.

## 6. Рекомендуемая GSAP-архитектура

```js
const mm = gsap.matchMedia();

mm.add({
  desktop: '(min-width: 993px)',
  mobile: '(max-width: 992px)',
  reduceMotion: '(prefers-reduced-motion: reduce)',
}, (context) => {
  const {desktop, reduceMotion} = context.conditions;
  const decor = gsap.utils.toArray('[data-gsap-decor]', section);

  if (reduceMotion) {
    gsap.set(decor, {clearProps: 'transform,opacity,visibility'});
    return;
  }

  decor.forEach((element) => {
    // Создать timeline по data-gsap-decor и desktop/mobile параметрам.
    // Trigger — ближайшая секция-владелец, а не document.
  });
});
```

Организация кода:

1. Общий модуль `initDecorAnimations(section)` читает data-атрибуты и создаёт timelines.
2. Entry point каждой секции передаёт только собственный root.
3. Все timelines и ScrollTrigger создаются внутри `gsap.context()`.
4. Cleanup вызывает `context.revert()` и `matchMedia.revert()`; повторный mount сначала удаляет предыдущий instance.
5. Для scroll-driven декора используется `ease: "none"`; для `reveal` — короткий `power2.out`.
6. `will-change: transform` включается только на реально анимируемых элементах, а не глобально для всех изображений.

## 7. Reduced motion

При `prefers-reduced-motion: reduce`:

- не создаются ScrollTrigger и scrub timelines для декоративных изображений;
- декор сразу отображается в своей CSS-позиции;
- `transform`, `opacity` и `visibility`, добавленные GSAP, очищаются;
- контент остаётся полностью доступным и не зависит от завершения анимации.

## 8. Проверка реализации

### Функциональная

- На странице анимируются только элементы с `data-gsap-decor`.
- Ни один `img`, `picture`, `coral-image` или content background не получает inline `transform`/`opacity` от GSAP.
- При повторной инициализации количество ScrollTrigger не увеличивается.
- При смене mobile ↔ desktop старые timelines удаляются, новые получают корректную амплитуду.
- Скрытые country panels не создают активные triggers до активации; после открытия выполняется `ScrollTrigger.refresh()`.

### Визуальная

- Проверить `428`, `768`, `1024`, `1280` и `1920 px`.
- На крайних значениях timeline декор не перекрывает текст и controls.
- В секциях нет горизонтального overflow.
- Начальная CSS-композиция совпадает с макетом до загрузки JavaScript.
- При reduced motion страница визуально завершена и не содержит скрытых элементов.

### Производительность

- Анимируются только `transform` и `opacity`.
- Не анимируются `top`, `left`, `width`, `height`, background-position и filter.
- Для крупных фоновых слоёв не используется scale выше `1.03`.
- Количество одновременно активных крупных scrub-слоёв ограничено двумя на секцию.

## 9. Итоговое решение

Единица анимации — не файл изображения и не breakpoint, а декоративная роль внутри конкретной секции. Desktop и mobile используют один DOM и один инициализатор, различаются только амплитудой и допустимостью движения. Контентные изображения всегда статичны; адаптивный crop и движение карусели не меняют это правило.
